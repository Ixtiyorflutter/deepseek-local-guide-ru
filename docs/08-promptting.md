## Рекомендуемые параметры сэмплинга

| Модель | temperature | top_p | Прочее |
|---|---|---|---|
| R1 и дистилляты R1 | **0.6** (0.5–0.7) | 0.95 | Без системного промпта или минимальный |
| V4 (Flash / Pro) | **1.0** | 1.0 (агенты — 0.95) | `min_p 0.01` в llama.cpp |
| Генерация кода / JSON без размышлений | 0.0–0.3 | 0.9 | `think: false` |

> Слишком низкая температура у R1-моделей приводит к **зацикливанию** рассуждений, слишком высокая — к бессвязности.

## Правила для «думающих» моделей

1. **Не пиши «думай пошагово»** — модель и так рассуждает. Лучше опиши задачу и критерии хорошего ответа.
2. **Ставь задачу полностью в одном сообщении**: контекст → задача → формат ответа.
3. **Для R1:** важные инструкции — в сообщении пользователя, системный промпт короткий или пустой.
4. **Математика:** «Рассуждай пошагово и помести итоговый ответ в `\boxed{}`».
5. **Few-shot (примеры) часто ухудшают** результат у reasoning-моделей — сначала пробуй zero-shot.
6. **Ограничивай длину** через `num_predict` / `max_tokens`, иначе модель может думать тысячи токенов.

## Когда включать размышления

| Задача | Режим |
|---|---|
| Математика, логика, алгоритмы, отладка | ✅ think (V4 — high/max) |
| Сложный анализ документа | ✅ think |
| Перевод, перефразирование, саммари | ❌ no-think |
| Извлечение в JSON, классификация | ❌ no-think |
| Чат, болтовня | ❌ no-think |

## Шаблоны промптов

### Строгий русский язык (для дистиллятов)

```
Ты отвечаешь ТОЛЬКО на русском языке, даже если вопрос на другом языке.
Если не знаешь ответа — так и скажи.
```

### Код-ревью

```
Проведи ревью кода ниже. Найди: 1) баги, 2) уязвимости, 3) проблемы производительности.
Для каждой проблемы: строка, суть, исправленный фрагмент. В конце — итоговая оценка 1–10.

<код>
...
</код>
```

### Извлечение данных

```
Извлеки из текста все компании и суммы сделок.
Верни ТОЛЬКО JSON-массив вида [{"company": str, "amount_rub": number}] без пояснений.

Текст: ...
```

### Анализ длинного документа (V4, контекст 1M)

```
<документ>
...весь договор...
</документ>

Задача: найди пункты, невыгодные для Исполнителя. Для каждого — цитата, риск, предложенная формулировка.
```

> 💡 Длинный документ ставь **в начало**, вопрос — **в конец**. Модели лучше работают, когда задача идёт после контекста.

## Работа с `<think>` в коде

```python
import re

def split_reasoning(text: str):
    m = re.search(r"<think>(.*?)</think>", text, re.S)
    thinking = m.group(1).strip() if m else ""
    answer = re.sub(r"<think>.*?</think>", "", text, flags=re.S).strip()
    return thinking, answer
```

**Фишка:** в истории диалога храни только `answer` — так экономится контекст, и модель не «залипает» на старых рассуждениях.
