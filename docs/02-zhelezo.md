## Главная формула

```
Память ≈ (Параметры × Бит на вес / 8) + KV-кэш + ~1–2 ГБ накладных
```

Примеры для весов (без KV-кэша):

| Модель | FP16 | Q8_0 (~8.5 бит) | Q4_K_M (~4.8 бит) | Q3 (~3.5 бит) |
|---|---|---|---|---|
| 8B | 16 ГБ | 8.5 ГБ | ~5 ГБ | ~3.5 ГБ |
| 14B | 28 ГБ | 15 ГБ | ~9 ГБ | ~6.5 ГБ |
| 32B | 64 ГБ | 34 ГБ | ~20 ГБ | ~14 ГБ |
| 70B | 140 ГБ | 75 ГБ | ~43 ГБ | ~31 ГБ |
| V4-Flash 284B | 568 ГБ | ~162 ГБ* | ~155 ГБ* | ~103 ГБ* |

\* Для V4-Flash приведены размеры динамических квантов Unsloth (часть весов изначально в FP4/FP8, поэтому «Q8» не вдвое больше «Q4»).

## KV-кэш: скрытый пожиратель памяти

Каждый токен контекста хранит ключи/значения внимания. Для обычных моделей на 32K контекста это может быть несколько гигабайт. Модели DeepSeek (MLA в V2/V3, сжатое внимание в V4) хранят KV-кэш намного компактнее, но дистилляты на Qwen/Llama такой экономии не имеют.

**Как уменьшить:** квантизация KV-кэша (`q8_0` — почти без потерь, `q4_0` — заметнее), flash-attention, разумный `num_ctx`.

## Какую квантизацию выбрать

| Квант | Качество | Когда брать |
|---|---|---|
| Q8_0 | ≈ оригинал | Если памяти с запасом |
| Q6_K | отлично | Компромисс для 32B на 24+ ГБ |
| **Q5_K_M / Q4_K_M** | хорошо | **Выбор по умолчанию** |
| IQ3 / Q3_K | заметные потери | Огромные модели (V4-Flash, 70B) |
| IQ2 / 1-бит | сильные потери | Только чтобы «влезло», для MoE-гигантов терпимо |

> 💡 **Правило:** большая модель в низком кванте обычно лучше маленькой в высоком. 32B-Q4 > 14B-Q8. Но ниже 3 бит качество падает резко (у MoE — мягче).

## Конфигурации под бюджет

| Бюджет | Железо | Что запустится |
|---|---|---|
| Ноутбук без GPU, 16 ГБ RAM | CPU | R1 1.5B–8B, 3–10 ток/с |
| Игровой ПК, RTX 3060 12 ГБ / 4060 Ti 16 ГБ | GPU | R1 14B на 100% GPU, 30–50 ток/с |
| RTX 3090 / 4090 / 5090 (24–32 ГБ) | GPU | R1 32B Q4; 70B частично в RAM |
| Mac M-серии 64 ГБ | Unified | 70B Q4 |
| Mac Studio 128–512 ГБ | Unified | **V4-Flash** Q3–Q8 |
| ПК: 128–192 ГБ DDR5 + RTX 4090 | Гибрид | **V4-Flash** с оффлоадом экспертов в RAM |
| NVIDIA DGX Spark (128 ГБ) | Unified | V4-Flash в 2–3-битных квантах |
| 8× H200 / B200 | Сервер | V4-Pro в FP8/FP4 через SGLang/vLLM |

## NVIDIA vs AMD vs Apple vs Intel

- **NVIDIA (CUDA)** — лучшая поддержка всего: Ollama, llama.cpp, vLLM, SGLang.
- **AMD (ROCm / Vulkan)** — Ollama и llama.cpp работают (ROCm на поддерживаемых картах, Vulkan — почти везде). vLLM — с ROCm на Instinct.
- **Apple Silicon (Metal)** — единая память делает Mac лучшим «бюджетным» способом запустить огромные модели. Узкое место — скорость обработки промпта.
- **Intel Arc** — через Vulkan/SYCL в llama.cpp.

## Как узнать, влезает ли модель

```bash
# NVIDIA
nvidia-smi
# Ollama: сколько модели на GPU
ollama ps        # колонка PROCESSOR: "100% GPU" — идеально
```

Если видишь `48%/52% CPU/GPU` — часть модели в RAM, скорость упадёт в разы. Уменьши контекст или квант.
